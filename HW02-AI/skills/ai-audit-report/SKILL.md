# AI Audit Report

## Overview

Create a course-ready AI Audit Report from a folder containing AI-assisted work. The report must preserve prompts and final AI outputs as evidence, ask the user for the condition of each AI output, and write a Markdown appendix matching the FIT@HCMUS Software Testing audit template.

When the user asks to include Codex chat logs, run `scripts/export_codex_chat.py` before drafting the report. When the user provides an AI-generated original file and a final edited file, run `scripts/compare_ai_final.py` and use the comparison as evidence for the audit row.

## Workflow

1. Identify the audit folder and output report path. If the user does not name an audit folder, use the current assignment folder. If the user does not name an output path, write `AI-Audit-Report.md` inside the audit folder.
2. Inspect the folder for evidence:
   - Prompt/output notes, Markdown files, text files, screenshots, PDFs converted to text, generated reports, and existing transcript files.
   - Files whose names contain `ai`, `audit`, `prompt`, `chat`, `codex`, `gemini`, `chatgpt`, `claude`, `copilot`, `output`, `domain-testing`, `bva`, or a feature ID.
3. If the user requested Codex chat logs, run:

```bash
python <skill_dir>/scripts/export_codex_chat.py --audit-folder <audit_folder> --workspace <workspace_root>
```

Use `--session latest` unless the user names a session file. The script writes a raw JSONL copy, a Markdown transcript, and an `ai-audit-interactions.json` file into the audit folder. The transcript and JSON should expose only the final AI answer for each interaction; the raw JSONL copy remains available if a complete technical log is needed.

4. If the user provides both an AI-generated original file and a final edited file, compare them before writing the audit row:

```bash
python <skill_dir>/scripts/compare_ai_final.py --ai-original <ai_file> --final <final_file> --output <audit_folder>/ai-final-comparisons/<name>.md
```

Use the generated comparison report to identify what the student changed, then explain why each meaningful change was needed.

5. Build one audit row per AI interaction or AI-generated artifact. Prefer explicit prompt/output pairs from transcript files. If an artifact was generated by AI but the prompt is missing, mark the prompt as `Not found in folder` and mention the evidence file.
6. Ask the user for the condition of each AI output before finalizing the table unless the verdict is already supplied in the folder. Use exactly one of:
   - `VALID`: usable without substantial correction.
   - `INVALID`: wrong, unsafe, off-topic, unsupported, or contradicted by the assignment/course material.
   - `INCOMPLETE`: partially useful but missing required cases, evidence, reasoning, formatting, screenshots, citations, or fixes.
7. Ask for missing student/course metadata only if it cannot be inferred. Keep the question short and grouped:
   - Student name
   - Student ID
   - Class/cohort
   - Assignment ID
   - Assignment date
   - AI tools used
8. Draft the report using `references/fit-hcmus-audit-template.md`. Preserve the five-section structure:
   - Student Information
   - Instructions
   - Audit Table
   - Declaration
   - Signature / Submission Checklist
9. Keep verbatim prompts and final outputs faithful. In the `AI Output` column, include only the final answer or final generated artifact content. Do not include chain-of-thought, hidden reasoning, progress updates, tool logs, status messages, or drafting process unless the user explicitly requests a raw technical appendix. If an output is too long for the table, include a concise excerpt in the table and link to the saved transcript, screenshot, artifact file, or comparison report.
10. Fill `Reasoning` with concrete review rationale. For testing homework, cite relevant sources such as ISTQB Foundation Level syllabus, course domain testing/BVA slides, assignment requirements, or the specific feature requirement file.
11. Fill `Student Fix` with the student's correction or a clear action item. If a final edited file exists, summarize the important differences from the comparison report instead of writing only `See final file`. Use `None` only when the verdict is `VALID` and no correction is needed.

## Evidence Rules

- Do not invent prompts, outputs, timestamps, or tool names. Use `Unknown` when evidence is missing.
- Keep all source files in place. Add generated transcript files inside the audit folder.
- Mention screenshots or image files by filename instead of embedding large base64 blocks.
- For Codex transcripts, use the exported Markdown or JSON interactions as evidence rather than copying internal system/developer messages into the report. Use the final assistant answer only as `AI Output`; do not report progress updates or implementation narration as the AI output.
- For AI-original vs final-file comparisons, cite the generated comparison report and explain human edits in the audit table.
- Exclude tool noise, shell output, hidden instructions, and environment context unless the user explicitly wants a raw log appendix.

## Final-File Comparison

Use this path when the user says they edited an AI-generated file directly and provides both the AI original and final file.

1. Confirm which file is the AI-generated original and which file is the final student-edited version.
2. Run `scripts/compare_ai_final.py` for text-based files such as `.md`, `.txt`, `.csv`, `.json`, `.yaml`, `.yml`, `.html`, `.css`, `.js`, `.ts`, `.py`, and extracted text from PDFs/DOCX.
3. If the files are binary or rich documents, first extract text using an appropriate local tool. If extraction is unavailable, compare filenames, metadata, screenshots, or user-supplied notes, and state the limitation.
4. In the comparison report, group differences by purpose:
   - Correctness fixes: changed wrong facts, wrong expected results, invalid test data, or incorrect domain classes.
   - Completeness fixes: added missing equivalence classes, boundary values, negative cases, prerequisites, evidence, or traceability.
   - Formatting fixes: reorganized tables, IDs, headings, numbering, screenshots, or submission-required structure.
   - Evidence/citation fixes: added references to assignment requirements, ISTQB, course slides, issue links, or screenshots.
   - Scope removals: removed hallucinated, duplicate, irrelevant, untestable, or unsupported content.
5. Explain each meaningful change in terms of the assignment requirement or testing principle it satisfies. Avoid treating typo-only or cosmetic changes as major correctness fixes.
6. Use the final-file comparison to set the verdict:
   - `VALID` if differences are only cosmetic, formatting, or small wording improvements.
   - `INCOMPLETE` if the final file adds missing but recoverable content.
   - `INVALID` if the final file replaces incorrect AI logic, wrong test expectations, hallucinated requirements, or unsafe advice.
7. Put a concise summary in the `Student Fix` column and link the detailed comparison report.

## Codex Chat Export

The export script searches `${CODEX_HOME}/sessions` or `~/.codex/sessions`, copies the selected session JSONL into:

```text
<audit_folder>/codex-chat-logs/
```

It also creates:

```text
<audit_folder>/codex-chat-logs/codex-chat-log.md
<audit_folder>/codex-chat-logs/ai-audit-interactions.json
```

Use the JSON file to populate audit rows. Use the Markdown file as the human-readable appendix reference. Both files are audit-focused and should show final answers only. The copied raw JSONL is the complete log backup.

Useful options:

```bash
python <skill_dir>/scripts/export_codex_chat.py --audit-folder <audit_folder> --workspace <workspace_root>
python <skill_dir>/scripts/export_codex_chat.py --audit-folder <audit_folder> --session <path-to-jsonl>
python <skill_dir>/scripts/export_codex_chat.py --audit-folder <audit_folder> --session latest --max-interactions 20
```

## Comparison Script

The comparison script writes a Markdown diff report that can be cited from the audit table:

```bash
python <skill_dir>/scripts/compare_ai_final.py --ai-original <ai_file> --final <final_file>
python <skill_dir>/scripts/compare_ai_final.py --ai-original <ai_file> --final <final_file> --output <audit_folder>/ai-final-comparisons/<name>.md
python <skill_dir>/scripts/compare_ai_final.py --ai-original <ai_file> --final <final_file> --context-lines 5
```

After running it, read the report and add human explanations. The script can detect changed, added, and removed text, but Codex must explain why those edits matter.

## Output Expectations

- Write a Markdown report unless the user requests another format.
- Use a compact Markdown table for short final outputs. For long outputs, place a reference in the table and store/point to the full output file.
- Never fill `AI Output` with the AI's thinking process, hidden reasoning, progress updates, or step-by-step internal work. Use only the final answer that was delivered to the user.
- For final-file comparisons, include a short bullet summary of the most important changes and link to the detailed comparison report.
- End with a checklist confirming that each AI-assisted artifact has a prompt, output/evidence, verdict, reasoning, and fix.
- If no AI was used, write the required declaration: `I do not use any AI help in this exercise.`
