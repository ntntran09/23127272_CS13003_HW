## **5\. Conclusion — When should AI be used (or not)?**

Based on the audit of twenty AI-assisted artifacts, clear patterns in AI performance emerged. AI was useful for creating reusable testing and audit skills, drafting initial domain-testing/BVA reports, extracting Codex chat logs, organizing the bug report from the four FR files, and assembling submission support files such as the prompt appendix and README. However, several outputs were incomplete because they followed the first prompt scope too narrowly, mixed UI and API scope when the final report required UI-only testing, placed corrections in a separate section instead of the main test tables, or required student-only values such as self-assessed grades and demo-video links. The strongest lesson from HW02 is that AI should be used for structured drafting, coverage brainstorming, and traceability work, but final expected results must still be checked against the README/spec and the course requirements. AI is not reliable enough to decide the final oracle by itself, especially when the current implementation contains bugs.
