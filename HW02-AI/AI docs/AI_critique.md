# AI Critique

During this assignment, AI was helpful for generating initial Domain Testing and Boundary Value Analysis reports, organizing the audit evidence, and suggesting possible bug candidates, but its output was often incomplete and needed careful human review. The clearest problem was that AI sometimes followed the first prompt too literally or chose the wrong testing scope. For example, the first FR-03 and FR-11 drafts mixed UI and API testing even though the final reports needed UI-only evidence, while the FR-02 draft focused too narrowly on the mobile login flow and initially missed related web login defects. AI also needed correction when deciding expected results: some expected outputs had to be rewritten according to the README/spec instead of accepting the current buggy implementation. This was important for cases such as failed-login counting, lockout duration, OTP length, password confirmation, shipping-order cancellation, and category validation. AI failed to catch these issues because it does not truly understand the product context or course requirement priority unless the prompt and evidence force it to compare each result against the specification. It is good at pattern generation, but weaker at knowing which source should be treated as the final oracle. The main principle I learned is that AI should be used as a drafting and coverage assistant, not as the final judge. A student must review every generated case, check the oracle against the requirement, remove scope drift, and add missing cross-feature cases before trusting the report.
